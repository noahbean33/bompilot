1. Provision Hetzner VPS

1

Create Server in Hetzner Cloud Console

  1. Log in to the Hetzner Cloud Console
  2. Click "Create Server"
  3. Select server type CX22
  4. Choose location (Nuremberg recommended)
  5. Select Ubuntu 24.04 LTS as image
  6. Add your SSH public key during creation
  7. Configure Hetzner firewall to allow only ports 22, 80, 443
  8. Click "Create & Buy Now"
Important

Note the server IP address after creation. You will need it for DNS configuration and SSH access.

2

Verify SSH Access

Terminal 
ssh root@

2. Configure Cloudflare DNS

In your Cloudflare dashboard for bomexplorer.app, add the following DNS records:

TypeNameContentProxy Status
AappProxied (orange cloud ON)
CAAbomexplorer.app0 issue "letsencrypt.org"DNS only
SSL/TLS Mode

Set Cloudflare SSL mode to Full (strict). With Cloudflare proxying enabled, Cloudflare handles the public SSL certificate. On the VPS you can use a self-signed or Cloudflare Origin CA certificate.

3. Server Setup

SSH into the VPS and install required software:

Terminal — System Setup 
# SSH as root
ssh root@

# Update system packages
apt update && apt upgrade -y

# Install Docker
curl -fsSL https://get.docker.com | sh

# Add ubuntu user to docker group
usermod -aG docker ubuntu
systemctl enable docker
systemctl start docker

# Install Git
apt install -y git

# Switch to non-root user
su - ubuntu
Security Note

Avoid running Docker commands as root. Use the ubuntu user for daily operations.

4. Clone Repository

Terminal — Clone Repository 
cd ~
git clone git@github.com:futureshocked/bomwise.git
cd bomwise
Authentication Options

Use SSH (git@github.com:...) if you have deploy keys configured, or HTTPS: git clone https://github.com/futureshocked/bomwise.git

5. Generate SSL Certificate

Option A: Self-Signed Certificate

Quick option. Cloudflare validates the certificate internally.

Terminal — Generate Self-Signed Cert 
sudo mkdir -p /etc/ssl/certs /etc/ssl/private
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout /etc/ssl/private/bomexplorer.key \
  -out /etc/ssl/certs/bomexplorer.pem \
  -subj "/CN=bomexplorer.app" \
  -addext "subjectAltName=DNS:app.bomexplorer.app"

Option B: Cloudflare Origin CA (Recommended)

Provides 15-year validity. Better for long-term deployment.

Terminal — Install Origin CA Cert 
# Create directories
sudo mkdir -p /etc/ssl/certs /etc/ssl/private

# Paste the certificate
sudo nano /etc/ssl/certs/bomexplorer.pem    # paste Origin cert

# Paste the private key
sudo nano /etc/ssl/private/bomexplorer.key   # paste Origin key
How to Get Origin CA Certificate

Go to Cloudflare dashboard → SSL/TLS → Origin Server → Create Certificate. Add hostnames: bomexplorer.app, *.bomexplorer.app. Download PEM files.

6. Install Nginx Reverse Proxy

Terminal — Nginx Setup 
# Install nginx
sudo apt install -y nginx

# Copy nginx configuration
sudo cp nginx/prod.conf /etc/nginx/sites-available/bomexplorer

# Enable site
sudo ln -s /etc/nginx/sites-available/bomexplorer /etc/nginx/sites-enabled/bomexplorer
sudo rm -f /etc/nginx/sites-enabled/default

# Test configuration
sudo nginx -t

# Enable and start nginx
sudo systemctl enable nginx
sudo systemctl restart nginx
Verification

If sudo nginx -t returns test is successful, the configuration is correct.

8. First Deploy

Run the deployment script from the project root:

Terminal — Deploy 
cd ~/bomwise
./scripts/deploy.sh

What the Deploy Script Does

  1. Pre-flight checks — verifies Docker, Git, and .env exist
  2. Git pull — fetches latest code from master branch
  3. Version tag — creates and pushes git tag from VERSION file
  4. Docker build — builds backend and frontend production images
  5. Container start — launches all services (postgres, redis, backend, celery-worker, celery-beat, frontend)
  6. Database migrations — runs Alembic upgrade head
  7. Cleanup — prunes old Docker images
  8. Health check — verifies backend responds on /docs
Ensure .env Exists

The deploy script will exit with an error if .env is missing. Complete step 7 before deploying.

9. Create Admin User

Option A: Via API (requires existing admin)

Terminal — Search for User

curl -X POST -H "Authorization: Bearer " \

Option B: Via Script (first admin)

Terminal — Make Admin via Script 
# Run inside the backend container
docker compose -f docker-compose.prod.yml exec backend \
  uv run python scripts/make_admin.py

Option C: Via psql (Fallback)

Terminal — Direct Database Update 
docker compose -f docker-compose.prod.yml exec postgres \
  psql -U bomexplorer -c "UPDATE users SET is_admin = true WHERE email = '';"

Rollback

If a deployment causes issues, you can quickly revert to a previous version:

Terminal — Rollback Steps 
cd ~/bomwise

# List available versions
git tag -l

# Checkout previous version
git checkout v1.0.0

# Rebuild and restart containers
docker compose -f docker-compose.prod.yml up -d --build

# If DB migration was involved, downgrade:
docker compose -f docker-compose.prod.yml exec backend \
  uv run alembic downgrade -1
Warning

Rolling back database migrations can cause data loss. Always create a backup before downgrading.

Troubleshooting

Backend Won't Start

Terminal — Check Backend Logs 
docker compose -f docker-compose.prod.yml logs backend

Common causes: missing .env variable, database not reachable, migration failed.

Celery Worker Not Processing Tasks

Terminal — Check Worker & Redis 
# Check worker logs
docker compose -f docker-compose.prod.yml logs celery-worker

# Verify Redis is running
docker compose -f docker-compose.prod.yml exec redis redis-cli ping

Nginx 502 Bad Gateway

  • Backend container not running → docker compose -f docker-compose.prod.yml ps
  • Nginx config wrong → sudo nginx -t
  • SSL cert issue → verify /etc/ssl/certs/bomexplorer.pem and key exist

Database Migration Fails

Terminal — Fix Migrations 
# Check current migration
docker compose -f docker-compose.prod.yml exec backend uv run alembic current

# Retry migration
docker compose -f docker-compose.prod.yml exec backend uv run alembic upgrade head

Admin Script Can't Find App Module

Terminal — Use psql Directly 
docker compose -f docker-compose.prod.yml exec postgres psql -U bomexplorer \
  -c "UPDATE users SET is_admin = true WHERE email = 'user@example.com';"

Security Checklist

  • ✓ Cloudflare proxy enabled (orange cloud on DNS record)
  • ✓ SSL certificate installed (self-signed or Origin CA)
  • ✓ .env file has strong SECRET_KEY and POSTGRES_PASSWORD
  • ✓ Only port 80/443 open to internet (Hetzner firewall)
  • ✓ PostgreSQL and Redis NOT exposed to public IP
  • ✓ CORS configured for https://app.bomexplorer.app only (production mode)
  • — Rate limiting on auth endpoints (built into FastAPI config)
  • — Paddle webhook signature verification active
  • — Regular backups configured (Hetzner snapshots or manual pg_dump)

Backup & Restore

Database Backup

Terminal — Backup Database 
docker compose -f docker-compose.prod.yml exec postgres \
  pg_dump -U bomexplorer -Fc bomexplorer > bomwise_$(date +%Y%m%d).dump

# Copy to safe location
scp bomwise_$(date +%Y%m%d).dump user@backup-server:/backups/

Restore from Backup

Terminal — Restore Database 
# Transfer dump file to VPS
scp user@backup-server:/backups/bomwise_20250101.dump .

# Restore
docker compose -f docker-compose.prod.yml exec -T postgres \
  pg_restore -U bomexplorer -d bomexplorer --clean < bomwise_20250101.dump
Danger

The --clean flag drops existing objects before restoring. Ensure you want to overwrite the current database.

Automated Backups (Recommended)

Set up a cron job on the VPS for regular backups:

Crontab — Daily Backup at 2AM 
# Add to crontab: crontab -e
0 2 * * * cd /home/ubuntu/bomwise && docker compose -f docker-compose.prod.yml exec postgres pg_dump -U bomexplorer -Fc bomexplorer > /home/ubuntu/backups/bomwise_$(date +\%Y\%m\%d).dump && find /home/ubuntu/backups -name "bomwise_*.dump" -mtime +7 -delete

This keeps the last 7 days of backups and auto-rotates.
